# 受理启动的瞬间把参数冻结成只读运行计划

`0x30` 的控制码为启、启动门槛通过的那一刻，`params_freeze()` 把当前序列参数、触发参数、电压、阈值与
6 档标定的换算结果复制进 `struct pulse_plan`（值语义，数组内联，约 2 KB，静态 RAM），之后脉冲引擎只读它。

这样"运行中改参数被拒"不是靠判定顺序，而是靠引擎**根本拿不到可写引用**；标定即使被绕过写进 Flash，
也不影响已经受理的运行。Flash 里只有 6 档标定与版本、SN（E-009），其余参数复位即恢复默认。

放弃的方案：

- **计划只持有指向 `params` 的指针**：冻结降级成纪律，任何一处漏判就会在运行中读到被改写的配置。
- **计划只存编译后的时序，读回时再取原始值**：运行中会读一个可能已被改写的结构（`0x35` 读回时也要一致）。
- **不冻结、靠命令层拒绝**：与 F-026 的字面要求不符，且把安全属性押在一条 if 上。

## Consequences

- `params` 与 `pulse` 之间只有一个数据通道：`struct pulse_plan`。
- 启动门槛（未配置、未设序列、过流检出、bit1）一次在 `params_gate()` 里判完，返回符号化原因，
  由命令层映射成 `0x13`/`0x11`/`0x15`/`0x12`。
- 计划是静态分配的，大小随「20 群 × 22 B + 6 档标定」封顶，RAM 预算可控。
