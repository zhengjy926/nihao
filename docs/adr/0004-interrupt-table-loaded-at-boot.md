# 中断由启动期装载，不引入构建期代码生成

上游把 `IRQ_CONNECT` 的登记留在链接产物里，再由 `gen_isr_tables.py` 生成向量表与软件分发表；本工程改为在启动期遍历同一批登记项、自行建立分发表，向量表继续由启动文件的默认入口按异常号转交。这样选是因为生成器必须吃链接产物，无法前移到配置快照阶段（ADR-0002），一旦采用就要把 python 与两遍链接塞进 Keil 构建。

## Considered Options

- **上游 `gen_isr_tables.py`**：语义保真最高，但需要两遍链接加 `pyelftools`；启动文件的向量表要让位给生成的链接片段，并引入上游 `_isr_wrapper` 的异常出口路径。
- **为每个向量手写 `XXX_IRQHandler`**：零机制成本，但每加一个外设就要改启动文件，`IRQ_CONNECT` 的声明被架空。

## Consequences

- 分发表占 RAM（每个可分配 IRQ 一项）而不占 Flash；启动期多一次线性装载。
- `IRQ_DIRECT_CONNECT` 与多级中断聚合器不可用；需要时重新评估。
- 中断处理函数里不得调用日志处理点：日志处理点会等待 DMA 完成，若 DMA/USART 完成中断的优先级更低就会优先级反转死锁。中断里只登记日志消息，回主循环处理。
- 会调用日志处理点的上下文，其被抢占的中断优先级必须高于 DMA/USART 中断。
- 接收侧缓冲按环形形状实现、当前两槽：主循环出现超过"两槽容量除以波特率"的阻塞时，增加槽数而不是更换机制。
