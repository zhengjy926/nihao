# 非易失记录用双 bank 上的 A/B 页，全仓只有 services/nv 能写 Flash

四类记录（软件版本、硬件版本、SN、6 档标定）各占一组 A/B 页，页大小 2 KB（G4 双 bank）。
记录格式 = 版本号 + 序号 + 长度 + 数据 + CRC32。提交顺序：活动页内追加新记录（序号递增）并写 CRC、校验；活动页写满时才擦非活动页 → 把最新记录写入 → 改活动标志 →
擦旧页。掉电发生在任一步，另一端仍是完整的旧记录。

NV 放在 bank2、代码留在 bank1：G4 的双 bank 支持跨 bank 的读-写并行，擦 bank2 期间从 bank1 取指不停流，
因此"擦除停住取指几十毫秒"只在单 bank 假设下成立。写 Flash 仍然只在**空闲期主循环**执行，不与出波并发。

放弃的方案：

- **每次写入都擦页**：编程只能把 1 写成 0，同一页可以反复追加，只有页满才需要擦。按"页内追加、满页才擦"
  设计，擦除频率从"每次写入"降到"每页一次"。
- **整扇区双区（每 bank 128 KB）**：余量更大但擦除更慢，且必须走长耗时命令模式，而协议只给了
  0x0A/0x0E 两种结果事件，扩一条的代价高于收益。
- **外部存储**：板上没有。
- **允许 `calib` 或 `params` 直接写 Flash**：会让"掉电回退旧区"这条保证散落到多个模块里。

## Consequences

- 记录层是 `services/nv` 的私有实现，对外只暴露 `nv_read`/`nv_write` 两个函数。
- 标定的反插与外推留在 `services/calib`，`nv` 只管字节。
- 擦写实际耗时与 RWW 行为需要在台架上确认（设计文档 §14 风险 5）。
