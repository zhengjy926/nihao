## 2. 设计目标

1. **高内聚**：一个模块只有一条生命周期、一个状态 owner、一个修改理由。
2. **低耦合**：模块之间只通过少数窄接口与值语义数据交互；协议层不知道 HRTIM，执行层不知道命令码。
3. **时间域分离**：纳秒级出波在硬件与最高优先级中断里闭环；毫秒级策略在主循环；协议解析不进入中断（N-003）。
4. **可主机测试**：编解码、校验、标定换算、累加与结算、NV 记录编解码不依赖 Zephyr 设备模型、内核或驱动头（唯一允许纯算法头，见 §12），可被任意 C 编译器编译。
5. **安全关断不依赖软件及时性**：过流停波由 COMP→HRTIM FLT 硬件链路完成（E-001）。

### 2.1 非目标

- 不把整板做成"只认协议命令"的从机大状态机。
- 不在 `services/` 里出现板级事实（杆的数量与引脚映射、档位电压值与档数、命令码语义）；领域概念（杆对循环、杆选通、标定换算）可以留在 `services/`。
- 不为低功耗与在线升级预留实现（I-031：未实现命令统一回 `0x04`）。

## 3. 分层与依赖

```
app/
  main.c                         应用入口和超级循环
  app.c, app.h                   实例、推进顺序、启动和边沿交接
  psg_hw.c, psg_hw.h             驱动适配和板级装配
  psg_cmds/psg_cmds.c, .h         板卡命令表、载荷编解码
services/
  ecsp/ecsp.c, .h                解帧、分派、会话和事务
  pulse/pulse.c, .h               脉冲引擎状态机
  pulse/pulse_hw.h                脉冲引擎所需的硬件操作
  pulse/pulse_plan.h              运行计划及其领域值类型
  params/params.c, .h             参数所有权、校验和计划构建
  calib/calib.c, .h               标定表、候选表校验和换算
  nv/nv.c, .h                     非易失记录和提交
drivers/
  pulse_timer/pulse_timer.c, .h   定时和寄存器换算
  current_capture/current_capture.c, .h  ADC DMA 和串边界交接
  protection/protection.c, .h     COMP、DAC 阈值路由和过流锁存
port/
  runtime.h                       应用侧运行时接口
  src/                            初始化、中断、时基和 Zephyr API 垫片
boards/psg/g474qet6/               启动汇编、设备树和板级配置
third_party/                       上游源码，只读
```

`app` 包含服务、驱动和 `port/runtime.h`，在 `psg_hw` 装配硬件接口。服务之间只依赖所需的值类型或公开接口，`services/` 和 `drivers/` 彼此不包含头文件。`boards/` 提供板级启动入口和配置，启动入口进入 `app/main.c` 的 `main()`。板级差异经配置快照和 `app` 注入的配置体现。

### 3.1 各层判据

| 层 | 判据 | 例 |
| --- | --- | --- |
| `app/` | 本板的对外契约与装配：命令码到功能域的映射、应答码映射、超级循环节拍、依赖注入。宿主与装配的**角色**换一块板/一个产品仍要有，但具体装配与命令集随板/产品重写；判据是"这段代码是否只为本板的对外行为与装配而存在" | 0x30–0x45 的命令语义与应答码映射、`main()`、装配与节拍 |
| `services/` | 换一块板仍然成立的功能域 | 帧编解码、会话、脉冲引擎、参数校验、标定换算、A/B 记录 |
| `drivers/` | 上游没有、或上游接口不覆盖本板用法的能力 | HRTIM 出波、ADC 采集、DAC 阈值路由 |
| `port/` | 上游源码要求、而本裸机运行时必须自己提供的 API | `sys_clock_announce_locked()`、`k_work_delayable` 轮询 |
| `boards/` | 换一块板就不同的板级事实（不参与 include 链） | CMSIS 启动文件、设备树、板级 defconfig/Kconfig、引脚复用 |

### 3.2 上游驱动的复用边界

| 能力 | 上游 | 本工程 |
| --- | --- | --- |
| GPIO / LED / UART / DMA / 时钟 / pinctrl / 复位 | 复用 | 已编入 |
| 比较器（COMP1/COMP3） | **复用** `drivers/comparator/comparator_stm32_comp.c`（LL 实现，配置与事件路径齐备） | 需按文件级选择新增 |
| Flash（擦写/页布局） | **复用** `drivers/flash/flash_stm32g4x.c` + `flash_stm32.c`（LL、双 bank 感知、锁用 `k_sem`，垫片已有） | 需按文件级选择新增 |
| ADC（电流采样） | 不复用：`adc_stm32.c` 把注入触发源写死为软件触发，且 `adc_context` 用 `k_sem` 阻塞等完成 | 自写 `drivers/current_capture` |
| DAC（比较器阈值） | 不复用：`dac_stm32.c` 只支持输出到引脚，不提供到 COMP 的内部路由 | 由 `drivers/protection` 管理 |
| HRTIM | **完全不存在**（无 binding、无 SoC 节点、无驱动） | 自写 `drivers/pulse_timer` |

**运行期契约**：从受理启动到运行退出，每个任务步骤都有执行预算，等待条件跨轮推进。调用上游 API 前须确认最坏执行时间。Flash 擦写只在空闲且 ADC 未采样时执行，擦写期间不受理启动。

## 4. 模块清单

| 模块 | 位置 | 拥有的状态 | 对外头文件 |
| --- | --- | --- | --- |
| 协议机制 | `services/ecsp/` | 字节环、解帧游标、会话状态、事务去重 FIFO(8)、事件队列(8)、上传模式 | `services/ecsp/ecsp.h` |
| 脉冲引擎 | `services/pulse/` | 运行状态与子态、串计数、电流异常记录、电流累加器、已完成触发次数、状态快照 | `services/pulse/pulse.h` |
| 参数 | `services/params/` | 8 类可配置项、序列参数表、默认值、校验 | `services/params/params.h` |
| 标定 | `services/calib/` | 电压档位时长标定表（档数与档位电压由板级配置定义，本板 6 档）、反插与外推 | `services/calib/calib.h` |
| 非易失 | `services/nv/` | A/B 页索引、记录格式、CRC、提交顺序 | `services/nv/nv.h` |
| 板级命令集 | `app/psg_cmds/` | 命令表、载荷解析、应答码映射、13 字节状态块序列化 | `app/psg_cmds/psg_cmds.h` |
| 宿主 | `app/` | 装配、节拍、超级循环 | `app/app.h` |

### 4.1 边界细则

- `ecsp` **不知道**板卡地址之外的任何板级事实；地址、命令表、运行状态查询函数由 `app` 注入。
- `ecsp` **不**解析载荷语义：长度与枚举之外的一切判断在命令处理器里。
- `pulse` **不**解析命令、**不**决定应答码；它只回答"能不能启动（符号化原因）"和"现在什么状态"。
- `pulse` 持有运行状态与电流异常记录，负责判定能否受理启动。`params` 校验配置并生成 `struct pulse_plan`，通过 `pulse_plan.h` 共享值类型，不包含脉冲引擎的状态机接口。
- `app/psg_cmds` 是唯一知道"哪条命令改哪个模块"的地方，也是唯一把领域结果映射成 `ecsp_reason` 的地方；`ecsp_reason` 到应答字节的映射由 `ecsp` 的 `ecsp_reason_to_ack()` 完成（§11）。
- 杆选通与杆对循环的配置值由 `params` 唯一持有。运行中经 `pulse_plan` 生效，空闲时由 `app` 将校验成功的 RAM 配置应用到板级输出。

## 5. 执行模型

### 5.1 上下文与优先级

| 上下文 | 优先级 | 职责 |
| --- | --- | --- |
| 过流锁存 EXTI（PG7/PG8） | 1 | 锁存事件及有效尾部样本（空闲时锁存沿 → 故障字 bit1） |
| HRTIM FLT | 1 | 锁存首个过流事件及有效尾部样本，硬件已停波 |
| HRTIM TIMA REP | 2 | 更新物理串计数、切换杆对、在群末禁止下一串启动 |
| 采样串边界 | 2 | 发布各通道已写入样本的结束序号，见 §5.3 |
| R 波 / 端口启停 EXTI | 4 | 向专用 FIFO 追加带时间戳的边沿 |
| UART / DMA | 6 | UART 交接字节，ADC DMA 跟踪缓冲进度 |
| SysTick 1 kHz | **15** | 只推进时间；不跑任何业务 |
| 主循环 | — | 协议解帧与执行、参数、结算、上报、日志、NV |

**关中断临界区**只允许做下标与标志交接：无循环、无 `LOG_*`、无浮点、无 `memcpy`，上限约 170 个周期。

### 5.1.1 主循环与事件交接

`app` 固定按脉冲引擎、ECSP、延迟工作、日志推进，每步限额。脉冲引擎先处理过流和输入交接错误，再按顺序处理边沿，并推进采样和运行状态。协议执行可能改变运行状态的命令前，由脉冲引擎重新检查待处理的保护事件和运行条件。运行期间只调度有界且不阻塞的工作。`port` 提供裸机启动所需的通用机制、时间、中断和同步原语，板级启动文件、链接布局和 SoC 配置由对应目标提供。服务各自拥有状态机和交接数据，系统采用专用通道，不设全局业务事件队列。

- **保护**：独立的粘滞锁存记录首个过流及其串归属、尾部样本。后续保护事件可合并，直到主循环取走，队列满载不影响保护。
- **触发与端口启停**：使用单个专用 FIFO 保持到达顺序。溢出时锁存输入丢失，禁止本轮继续受理边沿，运行中按停止路径退出。清理队列后重新同步端口电平，须等新有效边沿才重新启动。
- **串边界**：每串发布一条带串序号及各通道结束样本序号的记录。记录不可合并，满载时按采集失步处理。群结束可通过末串序号判断。
- **UART RX**：字节进入专用环形缓冲，满时记录丢字节并使受影响的解帧状态失效，随后重新同步。

### 5.2 时基

| 域 | 载体 | 覆盖 |
| --- | --- | --- |
| 硬实时 | HRTIM（预分频 `MUL2`，**2.941 ns/tick**）+ burst（**170 MHz ÷ 512**，**3.0118 µs/tick**，用 MUL2 之前的时钟） | 脉冲持续时间、脉冲间隔、极性间间隔、重复单元、**脉冲串间隔（burst 间隙）** |
| 软实时 | SysTick 1 kHz | 触发延迟、触发间歇、脉冲群间隔、结算等待、协议超时、心跳、日志节拍 |

不引入 TIM2/TIM5：串间隔已在硬实时域，其余毫秒级量的分辨率要求只有 1 ms（T-009），其输出精度要求 ≤ ±1 ms 且 ≤ ±1%（T-004）。

### 5.3 中断规则（唯一版本）

```
TIMA REP ISR：
  1. trains_remaining == 0 → 返回
  2. trains_remaining--
  3. 更新本群物理串完成计数
  4. trains_remaining > 0:
       杆对循环使能 → GPIOD->BSRR = 预计算掩码（一条写，无判断、无等待）
     否则（本群末串）:
       HRTIM 输出关断（一次写，防 burst 间隙结束后自动再起一串）
  不做：重装参数、换群、结算、累加、取平均、判欠流、读电流异常、写日志
```

- 参数重装只在**群边界**（主循环）。
- 换杆只在 REP（杆对循环使能时），杆对掩码由 `run_plan` 预计算。
- 过流：FLT 与锁存 EXTI 只做"抓尾部快照 + 置位"；六杆全断在任务上下文的异常处理里完成（E-001）。
- **采样**：每个启用通道使用连续环形 DMA，在群边界配置，群内不重装。DMA 半满和全满用于跟踪完整圈数，与剩余计数一起形成单调生产序号。快照须在回绕及中断待决时保持一致。主循环直接消费 DMA 缓冲，不复制到第二个样本环。
- **串归属**：在本串最后一次转换及 DMA 写入的最迟时刻之后、下一串首个采样之前，由硬件定时的串边界中断记录生产序号。仅在实测证明 REP 满足该窗口时，才在 REP 内发布记录。群末仍须捕获最后一条边界，不能用关闭波形输出替代。通过相邻结束序号切分实际样本，避免缺少一点评移后续各串。ISR 仅写入固定大小的记录，不搬运样本。
- **消费与结算**：主循环按已发布的边界分批累加，确认物理串已结束且未被过流截断之后，才把该串的和与点数纳入群和序列统计。提交前与过流锁存做短临界区交接，归约与浮点运算在临界区外。正常结算按实际取得的点数执行 F-038～F-042，缺样不会把后续串的数据算入本串。
- **容量与失步**：每通道容量须大于最大消费间隔内可能到达的样本数并留余量，串边界 FIFO 同样按该间隔的最大串数定容。计算须覆盖最短 1 ms 串间隔、每串最多 256 点和已排队的数据，并实测主循环最坏间隔、DMA 回绕记账服务间隔及持续消费吞吐。发现覆盖、边界溢出或生产位置无法可靠重建时，停止本次运行并记录采集失步，受影响数据不得作为有效统计。采集失步的协议呈现须由板卡规范定义。

### 5.4 电流异常的终止与处理

过流（比较器检出/锁存）属于**电流异常**，不属于故障字：**只发 0x3C，不置故障字、不发 0x11**（评审裁决）。

```
FLT / 锁存 EXTI 中断（优先级 1）：
  1. 清标志
  2. 首个事件记录串归属与 cc_snapshot_tail() 的结果（每路最多 2 个有效样本）
  3. 发布过流锁存
  不做：停 DMA、停 ADC、重配寄存器、求和、写日志

主循环的异常处理（任务上下文）：
  1. 先停触发源（停 HRTIM 计数 / 关 TIMB 的 ADC 触发）——顺序不能反，否则残留触发会置
     ADC 的 OVR，污染下一次启动的第一点
  2. cc_stop()：关两个 DMA 通道、清 ADC OVR 与 DMA 标志（幂等）
  3. 只结转过流前已完成且可可靠归属的串，丢弃异常串和之后的数据。
     依据首个过流锁存的串归属裁决，不能用 DMA 标志或样本数量推断该串完成。
  4. 六杆全断、运行指示拉低
  5. 发 0x3C：通道状态按 0x02/0x03，通道电流用快照 2 点平均
  6. 转"电流异常"，直到 0x3D
```

注意：FLT 只把输出掩成无效态，HRTIM 计数器仍在跑、TIMB 的 ADC 触发仍在发，所以"停触发源"必须显式做。下次采集前重置生产与消费序号、边界 FIFO 和锁存记录，再配置环形 DMA。

**未运行时的锁存过流**是唯一的例外，它属于**故障**：置故障字 bit1、按 §9 的门控与例外规则发 0x11，并阻止受理启动（E-003/F-004）；0x3D 在清除电流异常的同时做过流锁存复位，bit1 随之消失。它不进入"电流异常"状态，也不置通道状态字。

## 6. 数据所有权与运行计划

```
参数写命令 → app/psg_cmds 解码 → params 校验并更新 RAM
0x30 启动 ─┐
           ├→ app_request_start → params_build_plan → pulse_start
端口启动 ──┘
```

- `params` 是运行期配置的唯一 owner，**复位即恢复默认**（E-009）。
- `calib` 是时长标定表的唯一 owner；**Flash 里只有标定 + 版本 + SN**。
- `pulse` 只读 `pulse_plan`；运行中任何写命令被拒绝，因此计划不会半途改变（F-016/F-026）。
- `pulse_plan` 用值语义，数组内联。`app` 提供静态候选计划，`pulse_start()` 受理启动时复制到自己的上下文。启动失败时保留当前运行计划。两个缓冲均计入 RAM 预算。

## 7. 接口函数设计

约定：

- 返回 `int`，`0` 或负 errno；领域失败用独立枚举，不用魔法负值。
- 服务头文件提供完整上下文类型，`app` 静态分配实例。字段由所属模块读写，调用方通过公开函数操作。禁止动态分配和服务全局单例。
- 公开函数默认在主循环上下文调用。标明 `ISR` 的入口才可从中断调用，且只做固定预算的交接工作。
- 上行事件用 sink 结构体注册；服务不得直接发帧、不得直接调 `uart_tx`。
- 驱动以 `ops` 函数表注入，便于主机侧替身。

### 7.0 运行时和应用装配

```c
/* port/runtime.h */
void nihao_init_run_all(void);
uint32_t nihao_timestamp_get(void);
void nihao_work_poll(void);

/* app/app.h */
int app_init(void);
void app_task(void);
enum pulse_start_result app_request_start(enum pulse_start_src src, uint32_t now_ms);
int app_set_calib_tier(uint8_t tier, const struct calib_point *points, size_t count);
void app_on_edge(enum pulse_edge edge, uint32_t now_ms); /* ISR：边沿入 FIFO */

/* app/psg_cmds/psg_cmds.h */
const struct ecsp_cmd_entry *psg_cmds_table(size_t *count);
```

`app_init()` 调用运行时初始化、装配静态实例并启用输入。`app_task()` 先处理保护与输入丢失，再按 FIFO 分派边沿。端口启动调用 `app_request_start()`，端口停止调用 `pulse_stop()`，R 波传给 `pulse_on_trigger()`。`app_request_start()` 先调用 `pulse_check_start()` 判定运行状态、启停输入源和实时保护条件，再从已提交的参数和标定构建候选计划。配置失败映射为 `PULSE_START_PRECOND`。`pulse_start()` 在受理启动前重查实时条件。运行状态、启停输入源与保护条件的应答优先级遵守板卡规范。

### 7.1 `ecsp`

```c

				    struct ecsp_resp *resp);

	uint8_t product_addr;         /* 0x03 */
	uint8_t board_addr;           /* 0x02 */

 * 不解析、不唤醒（没有调度器，主循环自己轮询）、超出容量即丢弃并计数。 */

		     const void *data, uint16_t len);

bool ecsp_upload_mode(const struct ecsp *ctx);

```

`ecsp` 的解帧、握手、心跳、事务序号缓存、上传模式与待发调度属于同一个实例；`app` 静态持有实例并只注入时间、UART 字节与板卡命令，不查询会话状态来安排握手上报。`ecsp_task()` 每轮只消费给定的字节预算与至多一帧：解帧（**每轮上限 8 帧**，N-003）→ 地址过滤（不等即静默丢）→ 长度校验（`0x02`）→ 会话闸门（未握手且非 `0x01` 回 `0x10`，`0x04` 判定在其之前）→ 命令表分派 → 去重（命中则回放，不调 handler）→ 组帧发送 → 按预算推进事件发送。长耗时命令在协议推进中只做有界受理与即时应答，实际执行由应用后续推进，完成时把结果事件交给 `ecsp`。

`tx_submit()` 在主循环调用，区分三种发送结果：整帧被传输侧接管（复制到自身缓冲）、暂时忙（返回 `-EAGAIN`，`ecsp` 保留待发帧）、链路故障（帧未发出，可直接观测）。发送优先级：事务应答 → 故障等单次事件 → 周期握手/心跳，周期上报可合并。心跳静默期从 UART 确认整帧成功发送起算，入队或 DMA 接受不算成功发送。`ecsp_on_handshake()` 清去重 FIFO、停业务，并丢弃尚未交给 UART 的旧业务应答与事件（已交给 UART 的帧无法撤回）。`ecsp_post_event()` 复制有效载荷，队列满时返回 `-ENOSPC`。

## 8. 硬件装配（继承 v2 的实测配置）

### 8.1 HRTIM

| 项 | 值 |
| --- | --- |
| 预分频 | `MUL2` → 340 MHz 计数时钟，**2.941 ns/tick**，`ticks = ns*17/50` |
| TIMA | 输出 TA1→PA8、TA2→PA9；CMP1 置位 TA1、CMP2 复位；CMP3 置位 TA2、**PER 复位** |
| TIMA 周期 | `PER = ticks(脉冲间隔+150 + 正宽 + 极性间+150 + 负宽)`，`REP = 波形个数−1` |
| 单极性 | 不用的通道比较值写 `0xFFFF`（永不匹配） |
| TIMB | 无输出，只发 ADC 触发：CMP3→ADC1（正窗口）、CMP4→ADC2（负窗口）；周期/REP 与 TIMA 同步 |
| 采样点 | 脉冲开始后 `100+150 ns`，且**必须严格小于 PER**（否则每群最后一点丢失） |
| FLT4/FLT5 | 内部源、极性高、计数阈值 2（≈12 ns 确认）、滤波无、blanking 使能、预分频 /1；挂在 TIMA 上，输出故障态 `INACTIVE` |
| burst | 单次模式、触发源 `TIMA_REPETITION`、`170 MHz ÷ 512`（3.0118 µs/tick，用 MUL2 之前的时钟）、`BMPER=BMCMPR=round(gap×1700/512)`、`OUT_IDLE_WHEN_BURST`、`RESETCOUNTER` |
| 启动顺序 | 清 FLT 计数 → 清 REP 标志 → 使能 REP 中断 → 清两计数器 → 使能 BM → 使能 TA1/TA2 → 使能计数 |
| 停止顺序 | 关输出 → 停计数 → 关 BM（顺序反了会在间隙中途恢复出波） |

### 8.2 采样与保护

- ADC1/ADC2 常规通道 1 次转换、12 位、由 HRTIM ADC 触发启动。启用的通道各有一块半字环形 DMA 缓冲，容量按 §5.3 的实测预算定值。持续时间为 0 的通道不启动 DMA。
- 累加器：`u64 sum + u32 count`，每通道各一组，另有"群起点快照"两组标记。
- 换算：`avg_raw*3.3/4095 * 35/0.893/1.37 / SENSE_GAIN`；`SENSE_GAIN` 待标定。
- COMP3（正，INP=PA0，INM=DAC3_CH1）、COMP1（负，INP=PA1，INM=DAC1_CH1）复用上游比较器驱动（DAC→COMP 内部路由无基线文档出处，待引脚表补充）；COMP→FLT 的交叉开关由 `protection` 配置。
- **PA0/PA1 同时是 ADC 输入与比较器正端**，任何重配成 GPIO 都会破坏采样或过流保护。

## 9. 协议栈要点

- 帧：`0xFA` | len u16 LE | 0x03 | cmd | 0x02 | 载荷 | CRC16-Modbus u16 LE | `0x0D`；`len` 是整帧字节数，`LEN = 9 + 载荷`；CRC 覆盖 `len[0]…载荷末`。
- **CRC 用上游 `crc16_ansi()`**（`<zephyr/sys/crc.h>`，等价于 `crc16_reflect(0xA001, 0xFFFF, buf, len)`，即 CRC-16/MODBUS），实现文件 `subsys/crc/crc16_sw.c` 入库。代价：`O(n·8)` 位运算，典型 10–30 B 帧约 5–10 µs，最坏 512 B 帧约 120 µs；每轮最多 8 帧，最坏约 1 ms，仍在 50 ms 预算内。
- **硬件 CRC 的接缝已经存在**：上游 `crc16_reflect()` 是 `__weak`，将来要用 STM32 CRC 单元时补一个强符号即可，帧层不动。上游 `drivers/crc/crc_stm32.c` 的 `crc_ctx` 支持 16 位多项式 + 输入字节反转 + 输出位反转，技术上能算 MODBUS；但它把 CRC 从纯逻辑层挪进设备 API（要 dts、Kconfig、配置快照，且 `crc_update` 走 `k_sem`），而收益只是一个常数级加速——**本版不上**；若实测吃紧，先换表驱动软件 CRC（约 1 µs/512 B），再考虑硬件。
- 解析**必须长度驱动**：无转义、载荷可含 `0xFA`/`0x0D`；坏帧静默丢弃，不回 NACK。
- 半包超时 50 ms；应答时限取 **≤50 ms**（比 SRS 的 100 ms 更严，两者都满足）。
- 去重 FIFO 8 笔，键 `(cmd, txn)`，命中**回放缓存帧、不调处理器**；握手请求到达时清空。
- 会话：未握手只受理 `0x01`，未定义命令回 `0x04` 且**判定先于** `0x10`。
- 每轮最多解析 8 帧。
- **0x11 上报条件**（I-030）：`上传模式为开` **或** `本会话内已收到过至少一条指向本板的合法命令帧`；满足且故障位 0→1 时立即上报，不受事件队列门控限制。本版 0x11 唯一来源是**未运行时锁存过流**置起的 bit1（bit0 因自检不实现恒 0）；运行中过流走 §5.4，只发 0x3C。
- 电流异常终止一次运行时：**过流不属于故障**，只发 0x3C、不发 0x11（见 §5.4）；若未来故障字位在运行中发生变化（本版无此场景），才先 0x11、后 0x3C。

## 10. 非易失与标定

| 记录 | 内容 | 位置 |
| --- | --- | --- |
| `NV_SW_VERSION` | 7 字节 ASCII `X.Y.Z.B` | bank2 一组 A/B 页 |
| `NV_HW_VERSION` | 7 字节 | 同上 |
| `NV_SN` | `SN` + 10 位数字 | 同上 |
| `NV_CALIB` | 电压档位标定表（本板 6 档） | 同上 |

页大小 2 KB（双 bank）。记录 = 版本 u16 + 序号 u32 + 长度 u16 + 数据 + CRC32。写入在**空闲期主循环**完成；页擦除受双 bank RWW 保护，不影响取指。

`0x44/0x45` 线格式（I-022，待产线确认）：

```
0x44 请求: 档位 u8 (1..6) + 点数 u8 (1..30) + N × (配置时长 u16 ns, 实际时长 u16 ns)
           配置时长严格递增，实际时长 > 0；载荷 2+4N ≤ 122 B
0x44 应答: 应答码（0x00/0x03/0x11/0x15/0x20）
0x45 请求: 档位 u8
0x45 应答: 应答码 + 档位 u8 + 点数 u8 + N × (配置时长 u16, 实际时长 u16)
```

| 未握手 | （会话层直接产生） | `0x10` |
| 运行中 | `ECSP_BUSY` | `0x11` |
| 启停输入源不匹配 | `ECSP_MODE` | `0x12` |
| 前置条件不满足 | `ECSP_PRECOND` | `0x13` |
| 电流异常态 | `ECSP_ANOMALY` | `0x15` |
| 写入失败 | `ECSP_FAILED` | `0x20` |

以 SRS V0.6 为准（I-011），取代协议 V0.2 中把电流异常态记为 `0x13` 的做法。

## 14. 待验证与风险

1. **DMA 换杆**：DMAMUX `HRTIM1_A` 请求（0x60）是否每次重复事件触发一次，需查 RM0440 并台架验证；验证通过后把 REP 里的 `BSRR` 换成 DMA，接口不变。
2. `+150 ns` 固定补偿的来源与是否需要随电压变化，待测量。
3. COMP→FLT 交叉连接的映射无文档依据（`MCU引脚功能映射表.md` 不含 FLT 内容），需在自检或台架确认。
4. `SENSE_GAIN`、`TURN_ON_DELAY_TIME`、`RISE_TIME` 均为占位值，待标定。
5. 双 bank 的 RWW 行为需在台架确认（擦 bank2 时 bank1 取指不断流）。
6. 0x44/0x45 布局待产线工具确认。
7. burst 分频的时钟源按「MUL2 之前的 170 MHz ÷ 512」书写，但「340 MHz ÷ 1024」也能得到同一 3.0118 µs/tick；需按 V2.0 的 BPSC 寄存器核对后落定。
